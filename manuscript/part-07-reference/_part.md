# Part VII — Reference and Application

**Engineering thread — Make every consequential claim traceable.** This final part is a working reference for the enterprise system described throughout the book, not a new architecture or a new agent implementation. A useful reference lets an engineer start with a responsibility or contract, locate a concrete module or test when one exists, recognize when the reference implementation stops, and state the evidence needed before live deployment.

The shared case remains **CASE-204**, a proposed **$500 customer refund**. **RF-1042** is a trusted financial operation, never an authority conferred by an investigative agent's recommendation. **Design A** is the deterministic alternative, **Design B** uses bounded AI advice with independent financial authorization, and **Design C** optionally coordinates specialist investigation while preserving that boundary. These are alternatives; the six Python builds are independently runnable instructional checkpoints rather than one end-to-end deployment.

**Chapter 35 — Contracts, Schemas, and Reference Artifacts** provides a compact reader-facing way to navigate logical responsibilities, cross-domain contracts, typed identifiers, durable state, example evidence and independent control obligations. It distinguishes demonstrated fixture behavior from specified but unimplemented enterprise protections. **Chapter 36 — Exercises, Reviews, and Adoption Roadmap** applies that reference through integrated decision scenarios, hostile-path verification, failure recovery, release judgments and a bounded adoption plan. Its exercises are professional decision aids, not an additional agent architecture or Build 6.

Readers may enter Part VII from architecture, code, security, operations, governance or economics. Appendix A remains the contract quick reference; Appendix B maps the companion code; Appendix C distinguishes test evidence from release assurance. Follow the chapter's exact paths rather than assuming diagrams prove physical process isolation or provider correctness. Production certification, source-page verification and final whole-book print inspection are separate publication and deployment gates.
